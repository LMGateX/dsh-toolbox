# Migration host audit — DSH 0.2.2-alpha.3

Read-only source inspection of the installed baseline; no active profile, source plugin, package installation or GUI mutation was performed. Version confirmed in [installed manifest](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/package.json#L1-L4>).

## Native interface and traps

- Profile locations, launch overlays and started bundles belong to [ProfileContext](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/types/profile-context.d.ts#L9-L29>). Actual layer priority is bundles, profile, HOME patch, launcher overlays, telemetry hard-disable, not merely bundle plus profile ([composition](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js#L1899-L1917>)). Compose with native patch semantics; do not merge arrays by hand.
- **A read-sounding helper can write:** loadProfileDirectory invokes dropRetiredBundles, which rewrites the profile manifest; readProfilePatches and configEditor.configuration transitively call it ([reader](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js#L1795-L1796>), [writer](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js#L1739-L1745>)). Pure inspection must read explicit files and use nonmutating resolution/composition primitives.
- Settings forms exclude disabled/no-fiber/no-volatile-schema entries ([filter](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-settings/lib/index.js#L413-L419>)). They cannot be the complete migration source. Preserve raw values, parent-disabled state, source package/version and explicit target fields independently. Loader retains raw disabled expressions and evaluates them at runtime ([disabled](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/cordis-plugin-loader/lib/index.js#L462-L480>)); migration must not execute expressions to guess policy.
- HMR is non-reentrant: runExclusive rejects when AsyncLocalStorage records an executing transaction ([queue](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-hmr/lib/index.js#L735-L760>)). A timer created within that context inherits it; setTimeout alone is not a safe way to call pluginManager/configEditor later. reconcileProfile requires that context instead ([assertion](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-hmr/lib/index.js#L1325-L1328>)). Never await migration from plugin apply, nor await the current Loader task from its own startup.
- Native lock order differs: plugin manager acquires package.json file lock before HMR ([lock](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js#L3160-L3187>), [HMR](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js#L3093-L3099>)); config editor acquires HMR before the same lock ([edit](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-config-editor/lib/index.js#L69-L75>), [outer queue](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-config-editor/lib/index.js#L130-L133>)). Do not wrap those public mutations in another queue/lock or claim a universal native transaction. Bounded acquisition and revalidation must fail closed under contention.
- Ordinary config changes can dispose/restart the writing plugin, unlike validated volatile-only changes ([entry update](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/cordis-plugin-loader/lib/index.js#L498-L519>)). Durable journal recovery must survive that self-unload. Disposers must not wait for work that waits on their own recomposition.
- Host already watches profile patch, HOME patch and package manifest through HMR after application readiness ([watchers](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-hmr/lib/index.js#L830-L873>)). Native plugin management persists disabling without uninstalling packages ([row disable](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js#L2664-L2696>)); manual rows still require their own disabled override after bundle deselection.
- Native atomic write gives rename consistency but explicitly not fsync crash durability; native lock is local-host/PID-namespace only ([contract](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-atomic-write/lib/types/index.d.ts#L30-L85>)). Journal implementation must state its durability and shared-filesystem limits, not claim multi-file atomicity.

## Feasible no-host-modification implementation

Use a deep migration module: pure detached planner plus profile-scoped native adapter/storage executor. First-load bootstrap registers onReady and schedules a non-awaited persistence-only task. The task never invokes HMR, pluginManager, configEditor or Loader writes, so inherited HMR async context is immaterial. It prepares a permission-restricted backup/journal, validates, imports target module config while runtime gate remains closed, disables legacy rows and bundle selection, then returns; host-owned watchers do recomposition. Re-started Toolbox reads the same journal and only opens host gates after all matching legacy fibers are absent/disposed. No HMR means saved/restart-required, not applied. An in-flight unload/restart must not erase progress.

Browser static reconciliation removes unwanted managed entries and awaits disposal before new mounts ([order](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-client-modules/lib/client.js#L517-L547>)); source detection skips disabled rows ([host roster](</home/dev/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-client-modules/lib/index.js#L908-L914>)). This is page-local, not an acknowledgment from every disconnected old tab or unmanaged client plugin. Existing chime decode/play timers cannot be cancelled by replacement code: conservatively keep migrated chime gated until a fresh page/host generation establishes safe startup. Publish restart/page-reload-required explicitly.

Combined and split artifacts must share planner/storage code and per-capability ownership rules. Distinct splits coexist; a combined plus same-capability split conflicts rather than running both. A journal marker is per profile/module/source, never just package version.

## Release test obligations

Pure planner matrix: all/partial/disabled/absent sources, custom and historical ids, explicit false/zero/empty arrays, historical defaults, unknown versions, duplicate rows, dynamic expressions, higher HOME/launch overlays, peer distributions and experimental startup ownership. Executor matrix: concurrent engines/processes, native manager/editor contention, failure before/after every journal/write, process death and fresh retry, unchanged second run, self-unload, read-only/malformed profiles, selective rollback preserving newer fields. Native baseline tests must prove actual profile composition and old-row removal using disposable HOME/DSH_HOME only; emitted browser tests must prove no old chime timer overlaps activation. No live GUI or developer installation is a valid test fixture.
