# Migration implementation and native adapter

The public seam is exported by [migration index](../../src/migration/index.ts): startAutomaticMigration returns a synchronous controller with state/subscribe/settled/inspect/retry/rollback/dispose. Callers must not await settled from Cordis apply. The structural NativeMigrationHost accepts the native profileContext, loader.entries, appReady and get; optional moduleConfig reads the running root's volatile-unwrapped values. The planner accepts detached snapshots; native discovery uses only read-only native resolution/composition operations, never helpers that normalize profiles.

Persistence-only execution shares the native package.json writer lock with 1500ms bounded acquisition and never enters HMR, configEditor or pluginManager. Each profile/distribution journal lives under the private .dsh-toolbox directory. Backup, write intents, full step images and checkpoints precede profile mutations. Writes are permission-private, fsync payload and directory where supported, then atomic rename; there is no multi-file transaction or shared-host filesystem claim. A killed process can resume an exact-before/exact-after step; a concurrent edit pauses rather than overwrites. A bounded observer sees native lifecycle after the host-owned watcher reloads. Imported readiness also requires running target configuration to contain every expected field.

Raw configs are kept only in permission-restricted backups/journals, not public reports or CLI output. Completion is per profile/source/module and never reimports after a saved journal. Defaults support the audited exact source versions context 0.4.7, retry 0.1.9, chime 0.6.0 and goal wait 0.3.0. Historical unknown versions, dynamic fields and startup owners fail closed instead of assuming modern defaults.

Legacy chime migration persists browserReloadAfter epoch time and requires another host process plus a fresh browser page; root/client integration owns the page-served-at proof. No code cancels legacy audio closures from another package. Missing reload acknowledgment remains restart-required. No host restart is initiated.

Selective rollback is deliberately staged: first set only the requested imported module to disabled, preserving its config and unrelated later edits. Old bundle/manual ownership can return only after the original observed host PID is proven exited; live/reused/inaccessible PID stays blocked. A CLI-only journal that never observed a real target runtime cannot prove shutdown and therefore cannot automatically restore old owners. This is a fail-closed limitation, not a successful recovery claim. Exact owned disabled rows carry migration comments; if later rendering removed those markers or edited the module, recovery refuses to guess. Recovery write intents are themselves journaled and replay compare-before/after images. Turning Toolbox off does not restore old owners.

CLI build entry is [cli.ts](../../src/migration/cli.ts); expose as bin dsh-toolbox-migrate and package ./migration. Explicit --profile-dir, --dsh-home and --install-anchor are mandatory. --distribution chooses combined or one split. Commands inspect/dry-run/apply/retry/rollback; rollback requires --operation and --modules. CLI output omits raw config/user text. Offline CLI cannot report live application without native evidence.

Executed so far: 12 read-only discovery tests (including actual native alpha.3 helper YAML/!!js parsing), 7 planner tests, 20 executor fault/concurrency/two-process recovery tests. All use disposable HOME/DSH_HOME/profile fixtures; original source repositories and active profile are not used as a write target. Full native lifecycle/HMR proof is a separate test in progress; packed artifact/browser coverage belongs to integration and is not claimed by these source-level tests.
